# DSP 仕様書：BLIPPY BOOK 30（1台目）

後で JUCE（C++）や Rust（nih-plug など）に移植するための、音の処理の設計メモ。
コードは `src/toys/blippy/dsp/` にあり、DOM・Web Audio には一切依存しない。乱数は `src/core/rng.ts`。

## 全体の流れ

```
UI / MIDI / ホスト
   │ パラメーター値（src/toys/blippy/params.ts）・キー押下・電源
   ▼
Engine（engine.ts） ─── 1サンプルずつ処理
   ├─ Firmware（firmware.ts）  … 電源・起動・モード・クイズ。鳴らす波形と液晶の内容を決める
   │     └─ SoundBank（soundbank.ts） … 波形 ROM。8kHz・8bit の波形を作ってキャッシュ
   │           ├─ speech.ts … フォルマント音声合成
   │           └─ tones.ts  … 矩形波メロディ・効果音・ドラム
   ├─ Chip（chip.ts） … 再生回路。波形を「クロック」で読み出す（ゼロ次ホールド）
   │                     ＋ 魔改造配線：GLITCH 25種 / LOOP・LFO / STRETCH
   ├─ Dist（dist.ts） … 後付けの歪み（CLIP / FOLD+ビット落とし）
   └─ アンプ部 … 1次ローパス(6.5kHz) → DCカット → 音量 → 電源ゲート
   ▼
モノラル出力（Worklet ではステレオ両chに複製）
```

## パラメーター

`src/toys/blippy/params.ts` の `PARAMS` 配列がすべて（形は `src/core/params.ts`）。各項目は
`id / name / kind / min / max / default / labels / midiCC` を持つ。
DSP は `Float32Array(PARAMS.length)` で値を持ち、インデックスは配列の順番。

| kind | 意味 |
|---|---|
| continuous | ノブ（0..1） |
| stepped | 段階スイッチ。整数に丸める |
| toggle | 0/1 |
| momentary | 押している間だけ 1 |

VST3 化では、この表からそのままパラメーター一覧を作れる（momentary はホストのオートメーション対象外にしてもよい）。

## 乱数と再現性

- 乱数はすべて `rng.ts` の `Rng`（mulberry32、32bit 状態）。
- `hashSeed(...)`（FNV-1a の変形）で「個体シード＋用途名＋番号」から派生シードを作る。
  → 同じ個体シードなら、同じキーは必ず同じ音。
- 個体シードの既定値：`DEFAULT_SEED = 0x7a11c0de`（engine.ts）。
- Firmware 内のクイズ出題なども、個体シードから作った Rng を順番に消費するので、
  同じ操作列なら同じ結果になる。

## 波形 ROM（SoundBank）

- すべて **8000Hz**（`CHIP_RATE`）で生成し、ピーク 0.9 に正規化してから **8bit 量子化**（±127 段）。
- 生成結果は文字列キーでキャッシュ（例：`letter:K`、`drum:5`）。

### 音声合成（speech.ts）

簡易フォルマント合成。Klatt 型の直列共振器を使う。

1. 音素列（例 `"K AE T"`）を `phonemes.ts` の表で「区間」の列に展開。
   各区間：`F1,F2,F3`（Hz）、`av`（有声の強さ）、`af`（摩擦ノイズ）、`fn/fbw`（摩擦ノイズの中心と帯域）、
   `asp`（気息ノイズ）、`dur`（ms）。破裂音は「閉鎖→破裂→気息」の3区間。
   `next` 指定の区間はフォルマントを次の有声区間から借りる（H、破裂後の気息）。最後の母音は 1.45 倍に伸ばす。
2. 10ms（80サンプル）ごとの**フレーム**でパラメーターを更新（段差状＝LPCチップ風）。
   フォルマント周波数は前区間から min(40ms, 区間長/2) かけて直線補間、振幅は 12ms で補間。
   振幅はさらにサンプル単位で 3ms の1次平滑。
3. 音源：二乗余弦の声門パルス（開放率 0.6）を1次差分したもの × `VOICE_GAIN(6)`。
   ピッチは開始値→終了値（既定 0.72 倍）へ直線で下がり、前半に +6% の山、フレームごとに ±1.2% のゆらぎ。
4. 有声路：`(声門 × av + ノイズ × asp × 0.35)` → 共振器 F1(帯域70) → F2(100) → F3(150)。
   共振器：`y = a·x + b·y1 + c·y2`、`r = exp(-π·BW/fs)`、`c = -r²`、`b = 2r·cos(2πF/fs)`、`a = 1-b-c`。
5. 摩擦路：ノイズ → RBJ バンドパス（ピーク 0dB、Q = fn/fbw、fn は 0.47fs 以下に制限）× af × `FRIC_GAIN(2.0)`。
6. 出力 = 有声路 + 摩擦路 → ピーク正規化。

声の高さは個体ごとに 175〜214Hz（シードで決定）。

### 音声以外（tones.ts）

- 矩形波（50%/25%/12.5%）、三角波、ノコギリ波。位相累積のみ、帯域制限なし（わざと折り返す）。
- `melody`：音符列（MIDI番号, ms）。`decay` で指数減衰。
- `sweep`：指数カーブのピッチ変化。`noise`：サンプル保持・1次ローパス付きノイズ。
- ドラム8種（キック・スネア・ハット・オープンハット・タム・クラップ・カウベル・ザップ）、効果音10種を、
  キーごとに派生シードで細部を変えて生成。

## Firmware（モードとキー割り当て）

キー番号：0..25 = A..Z、26..29 = 機能キー F1(♪) F2(?) F3(★) F4(OK)、30..39 = ドレミの数字キー 1〜10（どのモードでも C5 から長音階の矩形波）

| モード | 文字キー | 機能キー |
|---|---|---|
| 0 ABC | 文字名の読み上げ（エー、ビー…） | ♪=メロディ ?=決まり文句 ★=効果音 OK=正解音＋GOOD JOB |
| 1 WORD | 単語（APPLE, BALL, CAT…） | 同上 |
| 2 TUNE | キーごとの短いメロディ | 同上 |
| 3 PIANO | ハ長調の音階（A=C3 から Z まで） | C/F/G/Am のアルペジオ |
| 4 DRUM | ドラム音（8種を循環） | 1小節のドラムパターン4種 |
| 5 SFX | 効果音（10種を循環） | ABC と同じ |
| 6 QUIZ | 出題された絵の頭文字を当てる。正解→ピンポン＋RIGHT、次の問題へ。不正解→ブッブー＋NO/TRY AGAIN | ♪=もう一度 ?=次の問題 ★=ヒント OK=GOOD JOB |
| 7 SAY | 「K IS FOR KING」 | ABC と同じ |

- **単音**：新しい音が鳴ると前の音は止まる（おもちゃと同じ）。
- 音が終わったとき Firmware の `onSoundEnd()` が呼ばれ、クイズの次の問題や起動後の画面切り替えを行う。
- 電源ONで起動音＋「HELLO」。鳴り終わるまでキーは効かない。
- LOOP スイッチが下（MUTE）だと電源が入らず、出力も無音。

## 再生回路（Chip）

- 読み出し位置 `pos`（チップのサンプル単位、小数）に `dir × 8000 × mul / hostRate` を毎サンプル足す（`mul` = クロック倍率）。
- 出力は `src[floor(pos)]`（ゼロ次ホールド・補間なし）。8kHz→48kHz の段差がそのまま折り返しノイズになる。
- `src` はふだん再生中の波形。VOICE 系グリッチ中は別の波形に差し替わる。
- 波形の終わりに来たら停止。ただし **GLITCH を押している間は止まらず**、波形の 0〜70% のどこかから鳴り直す。
- 1サンプルの処理順：
  1. 有効なグリッチの組み合わせ（25bit、`base*5+ボタン`）を求め、新しく有効になったものを初期化
  2. LFO（ホールド中のみ）でクロック倍率
  3. 位置・クロック・読み出し元を変えるグリッチ
  4. 読み出し（STUCK ADDR はアドレスに OR）
  5. データ線グリッチ（値を 8bit 符号なし `u = round(v·127)+128` にしてビット操作）
  6. ビープ系グリッチ
  7. 位置を進める → STUTTER の区間 ＞ LOOP ＞ STRETCH の順で折り返し
  8. 終端処理

### GLITCH（ボタン5個 × BASE 5位置 = 25種）

押している間だけ効く。複数同時押しは重ねがけ。タイミングはすべてチップの Rng（`hashSeed(seed,'chip')`）。
表中の「ランダム」は、その範囲から一様に選ぶ。時間はホスト時間。

| BASE | ボタン | 名前 | 動作 |
|---|---|---|---|
| 1 ADDR | 1 | SKIP | 25〜60ms ごとに、長さの 5〜30% 先へ飛ぶ |
| | 2 | STUTTER | 押した位置から 120〜560 サンプルを連打。長さは 250〜500ms ごとに変わる |
| | 3 | REWIND | 80〜160ms ごとに 400〜1600 サンプル戻る |
| | 4 | STUCK ADDR | 読み出しアドレスのビット 8〜11 のどれかが 1 に固定（300ms ごとに 40% で変更） |
| | 5 | REVERSE | 40〜90ms ごとに再生方向が反転 |
| 2 DATA | 1 | BIT FLIP | ビット 1〜6 のどれかを反転（20〜80ms ごとに変更） |
| | 2 | LOW BITS | 下位ビットを 0 に固定（マスク 0xE0/0xC0/0xF0 を 30〜120ms ごとに変更） |
| | 3 | MSB HIGH | 最上位ビットを 1 に固定（まれに 0xC0） |
| | 4 | NIBBLE SWAP | 上位4bitと下位4bitを入れ替え |
| | 5 | DROPOUT | 5〜40ms ごとに「そのまま／値を保持／無音」を切り替え |
| 3 CLOCK | 1 | SLOW | クロック ×0.5 / 0.25 / 0.33 / 0.66（押した時に決定） |
| | 2 | FAST | クロック ×2 / 3 / 1.5 / 4 |
| | 3 | WOBBLE | 8ms ごとの乱数（±0.9 オクターブ）へ 1次平滑（係数 0.004）で追従 |
| | 4 | STAIRS | 40〜90ms ごとに -12〜+18 半音のどれかへ段差で変化 |
| | 5 | STALL | 10〜60ms ごとに「停止（×0）」と「×1.6」を交互 |
| 4 BEEP | 1 | RUNAWAY | 振幅に比例した周波数（200 + |v|·3000 Hz）の矩形波を混ぜる |
| | 2 | RING MOD | 30〜900Hz の矩形波と掛け算（周波数はゆっくりずれる） |
| | 3 | BEEP ARP | 30ms ごとに 300Hz から 2 オクターブ内のランダムな矩形波。元の音がある間だけ鳴る |
| | 4 | NOISE GATE | 元の音の包絡（1次平滑 0.01）でノイズを鳴らす |
| | 5 | FEEDBACK | 直前の出力でクロックを変調（×max(0.05, 1+5·out)） |
| 5 VOICE | 1 | MISREAD | 同じモードの別のキーの波形を、同じ位置から読む（200〜350ms ごとに 50% で差し替え） |
| | 2 | SCRAMBLE | 60〜120ms ごとに、別のキーの波形のランダムな位置へ |
| | 3 | GARBAGE | 12〜30ms ごとに、別のキーかシステム音のランダムな位置へ |
| | 4 | MACHINEGUN | 押した位置へ 55〜125ms ごとに戻る |
| | 5 | HICCUP | システム音（起動音・正解音など）へ 50〜110ms 割り込み、120〜280ms 元に戻る、を繰り返す |

### LOOP

- **LOOP HOLD ボタン**：いまの位置の直前 400 サンプル（50ms）をつかんでループ（`loopStart = pos - 400`）。
- **LOOP RELEASE ボタン**：ループ終端（`loopStart + 400`）へ位置を進めて解除。STRETCH の周期もリセット。
- **LOOP スイッチ**：上(0)=自動ホールド。鳴り始め／リリース後に 900 サンプル（約110ms）進んだら自動でつかむ。
  中(1)=通常。下(2)=出力無音、電源も入らない。上から外すとホールド解除。
- ループ中は音が終わらない（新しいキーを押すと解除）。
- **LFO**（ループ中のみ）：正弦波。レート `0.1·2^(8·rate)` Hz（0.1〜25.6Hz）、深さ `±1.2·depth` オクターブのクロック変調。

### STRETCH

スイッチ ON の間、「普通に進む（RELEASE 区間）」と「200 サンプル（25ms）の粒を繰り返す（HOLD 区間）」を交互に行う。
- HOLD 区間の長さ：`15·60^hold` ms（15〜900ms）
- RELEASE 区間の長さ：`8·50^rel` ms（8〜400ms）
- インジケーター LED は HOLD 区間で点灯。ループ中は STRETCH より LOOP が優先。

## DIST（dist.ts）

`amount`（0..1、1次平滑 0.002）が 0.001 未満なら素通し。
- type 0 **CLIP**：`clamp(x·(1+40·a²), ±1) · (1-0.35a)`
- type 1 **FOLD**：`y = x·(1+8a)` を ±1 で折り返し（最大8回）→ `8-6a` ビットに量子化 → `·(1-0.25a)`

## アンプ部

- 1次ローパス：`lp += (x - lp) · (1 - exp(-2π·6500/fs))`
- DCカット：`y = x - x1 + 0.995·y1`
- 音量：`volume²` を 1次平滑（係数 0.002/サンプル）
- 電源ゲート：電源 ON かつ LOOP スイッチが下以外で 1。係数 0.01/サンプルで平滑（ポップ防止）

## 液晶の表示状態（DisplayState）

DSP 側は「何を表示するか」だけを決める：`screen`（off/boot/idle/key/quiz）、`mode`、
`big`（大きな文字）、`sprite`（ドット絵名）、`text`（下の行）、`mark`（ok/ng/q/dead）。
描画は UI 側（`src/toys/blippy/ui/lcd.ts`、128×64 の 1bit）。VST 版の UI も同じ状態から描けばよい。

## RESET

`reset` パラメーターの立ち上がりで、再生を止めて電源オフ状態にし、熱を 0 に戻す。電源 ON で起動し直す。

## 熱（heat.ts）

見えない「熱」`value`（0〜1.2）。固まる（フリーズする）ことはなく、手を離せば必ず冷める。

- 毎ブロック `dt` 秒ぶん更新。n = 押している GLITCH ボタン数（再生中のみ数える）。
- 上昇：`0.05 · n^1.7 · w[base] · (1 + 0.9·dist) · (1 + 0.35·ループ中 + 0.25·STRETCH中)` /秒
  （`w = [1, 1, 1.1, 1.2, 1.3]`）。グリッチ中にキーを押すと 1 回 +0.015。
- 冷却：グリッチを押していれば 0.02/秒、押していなければ 0.12/秒。
- **暴発**：熱が 0.4 を超えると、`(熱 - 0.4) × 8` 回/秒の割合で、押していないグリッチが 20〜150ms 勝手に入る
  （60% は今の BASE、40% は 25 種から）。熱 0.9 超では 50% で 2 つ同時。Chip の `forced`（25bit）に入れる。
- 目安（テスト結果）：GLITCH 1 個押しっぱなし → 約 18 秒で暴発開始、2 個 → 約 4 秒、3 個 → 約 2 秒。
  離すと 2〜7 秒で暴発が止まる。

## 状態の出力（status）

`Engine.status()` は UI 用に次を返す（Worklet から約 20ms ごと）。
- `leds`：`stretch`（0/1）、`loop`（0/1）、`glitch`（グリッチの効き 0..1）
- `fx`：`combos`（いま効いているグリッチ 25bit、暴発を含む）、`heat`、`seed`（Chip の乱数状態）、`misread`（誤読みしたキー）

液晶のグリッチ（`src/toys/blippy/ui/lcdfx.ts`）はこの `fx` だけから作る。`seed` と描画回数から乱数を作るので、
音と同じ状態から同じ崩れ方になる。組み合わせ 25 種ごとに崩れ方が違う（行ずれ・行の重複・ドット化け・横伸び・波打ち・反転・しま・ノイズ・キャラの入れ替えなど）。
VOICE の MISREAD/SCRAMBLE/GARBAGE 中は、液晶の文字とキャラが「誤読みしたキー」のものに変わる。

## 自分の声（mic.ts）

- UI の MY VOICE を押して待機 → キーを押している間だけマイクを録音（最長 4 秒）。
- `toChipSample`：区間平均で 8kHz に間引き → ピークの 8% 未満の前後を切る（前 10ms・後 50ms の余白）→ 0.9 に正規化 → 8bit 量子化。
  0.1 秒未満や無音なら `null`（そのキーの声を消す）。
- `Engine.setUserSample(key, buf)` でキーに割り当て。QUIZ 以外のモードでは、声が入っているキーは内蔵音の代わりに声を鳴らす。
- UI は 8bit の値をブラウザ（localStorage）に保存し、次回起動時にエンジンへ戻す。

## LINE OUT 録音・MIDI（UI 側）

- REC（アプリ上部、全おもちゃのミックス）：Worklet が出力（音量・歪み込み）を 8192 サンプルずつ UI へ送り、停止時に WAV（16bit ステレオ、ホストのサンプルレート）にしてダウンロード。
- Web MIDI（チャンネル1）：ノート 36〜75 → キー 0〜39（36=A … 61=Z, 62〜65=♪?★OK, 66〜75=ドレミ 1〜10）。
  CC は `params.ts` の `midiCC`（連続値は 0..127 を範囲に、段階は丸め、トグル/ボタンは 64 以上で ON）。
  CC 119 = 電源（64 以上で ON）。プログラムチェンジ = モード（0〜7）。

## おもちゃ1台のインターフェース（src/core/toy.ts）と今後の構想

`Engine` は `ToyEngine` インターフェースを実装する：
`params / paramDefs / setParam / keyDown / keyUp / powerOn / powerOff / process(out) / display / displayVersion / status()`。

将来、複数の改造おもちゃを並べて演奏し、それぞれをトラックとして録音・DAW へ書き出す（KORG Gadget のような）ホストを作る。
ホストは `ToyEngine` だけを知っていればよく、おもちゃを増やすときは同じ形のエンジンを追加する。
VST3 化するときも、`ToyEngine` 1つが 1 プラグイン（または 1 つのプラグイン内の 1 音源）になる。
