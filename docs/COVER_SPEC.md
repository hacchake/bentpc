# まねっこ（カバー）おもちゃ：仕様

取り込んだ曲（MP3・AAC・WAV など、ブラウザで読める音声ファイル）を解析して、選んだおもちゃ（何台でも）だけで同じ曲を作り直す（カバー）。
曲のファイルはこのブラウザの中だけで処理し、どこにも送らない。

## 段階

- [x] フェーズ1：曲の解析（`src/cover/analyze.ts`、DOM 非依存）
  - テンポ（出だしの強さの自己相関＋好みの範囲）→ 拍（動的計画法）→ 裏拍に寄っていたら半拍ずらす（キックの位置で判断）→ 小節の頭（和音の変わり目を主に、キックを少し）
  - 調（クルムハンスルのプロファイル）→ 移調（主音を C、短調なら A に）
  - 小節ごとのコード（ハ長調の 7 つの和音とのなじみ＋ベースの音を少し重く・ビタビで粘る）
  - メロディ（倍音を足した目立ち度・16 分ごとの多数決）・ベース（8 分の 1 に間引いた信号を細かく・8 分ごと）
  - ドラム（帯域ごとの出だし：キック 40〜130Hz、スネア 180〜900Hz＋1.5〜5kHz、ハット 7〜10.5kHz。曲全体の大きさを「床」にした対数の増え方）
  - 構成（小節ごとの特徴の自己相似から区切り → 大きさでイントロ・Aメロ・サビ・ブレイク・アウトロ）
- [x] フェーズ2：カバーを作る（`src/cover/plan.ts`）
  - 解析 → 設計図（Plan）。テンポ・小節数・構成・コードは解析どおり。`plan.cover` にメロディ・ベース・ドラムを入れる
  - 作曲係の共通の道具（`harmony.ts` の `drumBar`・`realize`・`bassLine`）が `plan.cover` を見て、作る代わりに解析の音を返す → 7 台どのおもちゃでもカバーになる。トイPC はドレミのキーでメロディ（1 音ずつなので声・ドラムより優先）
  - 曲データには解析結果（`compose.cover`、音そのものは入れない）を残す → セクションだけ作り直してもカバーのまま
  - スタイル（ビート・レゲエ・演歌…）は「どの楽器・どんな刻み方で弾くか」に効く（サンプラーの楽器セットなど）
- [x] ボーカルを取り出す（`src/cover/vocal.ts`、AI を使わない）：曲を「高さ × 時間」に分けて、①左右が同じ（真ん中）②伸びる音（ドラムではない）③歌の高さ（120Hz〜8kHz）④解析したメロディの倍音の近く、がそろう所だけ残す。残りは伴奏（カラオケ）。モノラルの曲でも動く（①なし）。`alignToGrid` で元の曲の拍の揺れをならし、カバーの一定のテンポにそろえる → カバーに元の歌を重ねられる
  - 答えのわかる曲で：歌のはっきりさ -5.3dB → 10.6dB（+15.9dB）、伴奏から歌が 65% 減る（`scripts/vocal-test.ts`）
- [x] フェーズ3：おもちゃ本体 MANEKKO MK-8（8 台目。`src/toys/manekko/`）
  - 見た目：インコの形のカセットレコーダー（頭・目・くちばし・とさか・しっぽ・カセットの窓とリール）に、モニター・ツマミの板をねじ止めした魔改造機
  - ⏏ LOAD（落としても可）→ `OfflineAudioContext.decodeAudioData` → Web Worker（`worker.ts`）で解析とボーカル分離 → モニターに進み具合
  - モニター：曲名・BPM・調・小節数・長さ・構成の色の帯（白い枠 = 使う範囲、光る線 = 再生位置）・小節ごとの大きさ・今から 8 小節のコードとメロディ
  - PLAY BY（弾くおもちゃ、いくつでも）・STYLE ◀ ▶・FROM / TO（範囲）・VOCAL ON（元の歌を重ねる）・CHAOS → COVER!（作ってシーケンサーに入れ、頭から鳴らす。押すたびにシードが変わる）
  - エンジン（`engine.ts`）：歌・伴奏・原曲のテープ（カバーの拍にそろえたもの）を、キー k = 「k 小節目から」で鳴らす（シーケンサーのどこから再生してもずれない。合わせ直すときは 6ms でつなぐ）。ツマミ：VOL・VOCAL・KARAOKE・ORIGINAL・WOW（テープのよれ）・LO-FI（こもり・歪み・サー）・ECHO（付点 8 分）・STUTTER（押している間 1/8 拍をくり返す）
  - 作曲係（`compose/toys/manekko.ts`）：カバーのとき 1 小節に 1 つテープの音符。合奏のブレイクでも消さない。ほかのおもちゃの自動作曲パネルには出さない
  - ▶ 原曲：押している間、元の曲だけ（聞きくらべ）
  - 曲のファイルはこのブラウザの IndexedDB（`manekko`）にだけ保存。開き直すともう一度解析する（解析結果は大きいので保存しない）
  - ホスト（ラック・スタジオ）は `HostApi.songHost`（並んでいるおもちゃ・曲をシーケンサーに入れる口）を渡す
- [x] フェーズ4：攻略本「まねっこ（カバー）編」（写真は、このアプリのおもちゃで作った曲を取り込んで撮る）・英語・長い曲は最初の 8 分だけ（スマホのメモリ）・権利の注意

- [x] 再現度を上げる（2026-10-05）
  - 2 回目の解析：歌を抜いた伴奏から調とコード（`refineHarmony`。歌の倍音に引っぱられない）、取り出した歌からメロディ（`melodyFromVocal`）
  - 調：「どの調の 7 つの和音で小節の響きを説明できるか」＋「調の 7 音に入っている割合」を 12 通りためす（長調と短調は音のプロファイル）
  - 小節の頭：和音の変わり目・キックに加えて「1 小節 = 1 つの和音にいちばん合う区切り」「ベースの根音が小節の中で同じ」
  - テンポは 70〜180 BPM の中で探す（2 拍ごとのアクセントで半分の速さにならないように）
  - 12 音は 2kHz まで・高い所ほど軽く（倍音の 7・11 倍音が調をずらさないように）。周波数の目の間を補って比べる（低い音で半音となりと取りちがえない）
  - ベースは「同じ高さが続く音」だけ（キックをベースの音とまちがえない）
  - 半音：白鍵に無い音も、半音のずれ（acc）で持つ → PIKOTONE・DJ・サンプラー・VROOMBOX は正しい高さで弾く（トイPC・TYPOTRON は白鍵だけ）
  - テープの調：カバーはハ長調で弾くので、歌・伴奏・原曲のテープも音程だけずらしてそろえる（`pitchShift`、WSOLA）
  - PAKU-PAKU 16 でカバーするとき：元の曲から 16 音を切り出して、空いているバンク（H〜P の後ろから。前に MANEKKO が使ったバンクはまた使う）に入れる（`src/cover/sampling.ts`）。キック ×2・スネア ×2・ハット ×2・オープンハット・クラッシュ・逆再生クラッシュ・ベース・長調の和音・短調の和音・歌の 1 音・歌の切れ端・伴奏 1 小節・歌 1 小節。音程のある音は高さを測って元の高さ（root）と微調整（fine）に。作曲係はこれでドラム・ベース・メロディ（歌声）・和音（長調／短調を持ち替えて根音だけ）を弾く。名前の頭に ♪
  - サンプラーのページ：ほかのページがパッドだけ保存していたら、工場出荷の音（A〜G）の空いている所を埋める

- [x] リズムの細かさ・解析と分離の精度を上げる（2026-10-05）
  - 物差し：答えのわかる曲を 8 曲作る（`scripts/lib/songgen.ts`。歌・ピアノ・ギター・パッド・ベース・ドラム・残響、ハネ・小節の途中のコードチェンジ・歌の左右を変える）→ `npm run bench`（`scripts/cover-bench.ts`）で点数
  - ハネ（スウィング）：拍と拍の間で出だしが集まる位置を探す（拍の出だしのずれは差し引く）→ `analysis.swing`。メロディ・ドラムの枠はハネを戻した位置で読み、カバーは元の曲のハネで弾く（`plan.style.swing`）
  - 拍のずれ：キックが拍の中のどこに集まるかを見て、そこを拍にする（半拍だけでなく、ハネた裏拍に引っぱられたときも）
  - 小節の途中のコード：半小節（2 拍）ごとにビタビ（小節の途中で変えるのは粘る）→ `analysis.chordsHalf` → `plan.chordsHalf`。伴奏は 3 拍目をまたぐ和音を 2 つに分ける（`hitsIn`・`chordAt`）
  - テンポ：拍の間隔はフレームの整数にならないので、自己相関を少しぼかして間の値も読む（140 BPM が 70 BPM にならない）。スネアが拍の間ばかりなら倍の速さ
  - ベース：2・3 倍音の無い低い音（キックの「ドン」）はベースとして数えない → コードが大きく改善
  - ボーカル：①歌の左右の位置をメロディの倍音から見つけ、その向きで取り出す（真ん中でない歌も）②2 回に分けて取り出す（`separateVocal`：1 回目は高さを使わず、取り出した歌から高さを聞いて、2 回目はその倍音の所だけ）③歌っているかは「大きさ × 倍音らしさ」が、まわり数秒の伴奏の残りよりはっきり大きい所
  - 物差しの点数（8 曲の平均、直す前 → 後）：テンポ 88 → 100%・小節の頭 75 → 100%・調 75 → 100%・コード 47 → 99%・途中のコード 70 → 99%・ハネ 75 → 100%・メロディ 59 → 79%・歌った所を拾えた 86 → 92%・分離 +9.2 → +13.2dB
  - 人が弾いたようなテンポの揺れ・音のずれのある曲も物差しに追加（10 曲）。拍をそろえてから「半分の速さか」を見る（ハネ＋揺れの曲が倍の速さになっていた）
  - 歌の高さはビタビでつなぐ（伴奏の残りが一瞬目立っても飛び移らない）。倍音から外れた所は 0.15 まで下げる
  - 10 曲の平均：テンポ・小節の頭・調・コード・ハネ 100%・途中のコード 99%・メロディ 77%・歌った所 91%・分離 +13.7dB
- [x] 伴奏の楽器ごとに外す（今までの取り出し方に足す形）
  - ベース：曲からベースの高さを聞き取り（`bassPitch`）、その倍音の線（1.5kHz まで）を歌から外す（3 割残す）。歌の倍音と重なる所は残す。ベースは真ん中で伸びる音なので、①〜④では残ってしまっていた
  - 10 曲の平均：メロディ 77 → 83%・歌った所 91 → 93%・分離 +13.7 → +14.0dB
- [x] ボーカル分離をさらに（2026-10-05）
  - 細かい高さ：半音ごとの高さから ±60 セントの中で倍音の山がいちばんそろう高さを探し、その倍音のまわりだけをなだらかに残す（ビブラート・半音の間の高さに追いつく）
  - 歌の高さがわかっている 2 回目からは、左右の位置をもっと厳しく見る
  - 3 回に分けて取り出す（2 回目の歌から聞いた高さで、もう一度）
  - 10 曲の平均：分離 +14.0 → +15.1dB（答えの高さを使った場合の上限は +16.8dB。差の多くは「歌っているか」の判定）・メロディ 83%
  - 試してやめたもの：仕上げのウィーナーフィルタ（変わらず）・歌っている所を前後に広げる（下がる）
  - まだ弱い所：歌っていない短い間にも音を出しがち（休みの 6 割）、歌と近い位置に同じ高さの楽器があると、メロディが 6 割ほど

- [x] 調の外のコード（2026-10-06）
  - 物差しに「調の外のコード」の曲を 3 曲（III・II の長三和音、iv の短三和音、♭VII・♭VI。短調では V の長三和音・IV の長三和音）
  - コードは 12 の根音 × 長・短（調の中なら減も）から読む（`chords24`）。まず調を決めずに読み、その並びが「調の 7 つの和音」にいちばん多く入る調＋主和音（I・vi）が長く鳴る調を選ぶ（12 音のなじみ方も少し足す）。その調の和音を少しひいきして読み直す
  - 解析は `chordQ`（ハ長調に移した根音と長・短・減）も返す。度数（`chords`・`chordsHalf`）は根音の近い白鍵の度数
  - カバー：`plan.chordAcc`（度数の三和音の根音・3 度・5 度を何半音ずらすか）。伴奏（PIKOTONE・サンプラー）は E なら G♯、B♭ なら B♭ で弾く（`hitMidi`）。切り出した和音のパッドも長・短を正しく持ち替える
  - 13 曲の平均：調 77 → 100%・コード 77 → 100%・調の外のコード 0 → 100%（今までの 10 曲は変わらず）

- [x] 本物らしい歌・厚い伴奏（2026-10-06）
  - 物差しに 3 曲：歌い方（音の頭のすくい上げ・音ごとの外れ・まちまちのビブラート・子音と息）、真ん中で鳴るシンセのアルペジオ・シンバル・歌が小さめ
  - 歌の高さ：倍音の山を、計算した位置ちょうどでなく ±2%（±35 セント）の中のいちばん大きい所で数える（ビブラート・外れに強い）。歌っているかの判定も、±60 セントの中の細かい高さの倍音で
  - 16 曲の平均：メロディ 81 → 88%・分離 +15.0 → +15.5dB
  - 試してやめたもの：目立ち度を時間方向にならす（変わらず）・対数で圧縮して数える（下がる）

- [x] メロディの音の頭（2026-10-06）
  - 物差しに「音の頭（リズム）」の点数（答えの音の頭の ±1/8 拍に聞き取った音の頭があるかの F 値）と、インストの曲 2 曲
  - 同じ高さの音の打ち直しを分ける：約 6ms ごとの細かい音量で「すぐ前でいったん下がって、また上がる」所（音の切れ目は数十ミリ秒しかないので、23ms ごとの大きさでは見えなかった）
  - 18 曲の平均：音の頭 54 → 66%。楽器のメロディ（インスト）は 96〜97%
  - 試してやめたもの：スペクトルの増え方（フラックス）も手がかりにする（変わらず）
  - まだ弱い所：残響が音の切れ目を埋める曲、歌っていない短い間の余計な音（休みの約半分）

- [x] 楽器ごとに分ける（ボーカル・ドラム・ベース・その他）（2026-10-06）
  - `splitInst`：歌を抜いた伴奏を、ドラム（時間方向と高さ方向の真ん中の値をくらべる HPSS。150Hz より下でベースの線でない所はキック）・ベース（ベースの音の名前の、いちばん低いオクターブからの倍音の線）・その他（ギター・キーボードなど）に。足すと伴奏に戻る。AI は使わない
  - ドラムの聞き取り：ドラムだけの音を NMF で「キック・スネア・ハットの 3 つの音色 × 鳴った量」に分け、鳴った量が急に増えた所を打音に（キックは強い所の 3 割、スネアは 5 割でキックと同じ枠なら 2 倍、ハットは対数の自然な切れ目）
  - ベースの聞き取り：ベースだけの音から。高さは「2 倍音が弱いのに 3 倍音だけ強い」候補を下げる（キックの低い音と本当の音の倍音が重なった 5 度下の読みちがい）
  - 物差しにドラムとベースの答え合わせと、ばらつきのあるドラムの曲 3 曲（小節ごとに違うキック・ゴーストのスネア・オープンハット・タムのフィル・シンバル・曲ごとの音色）
  - 21 曲の平均：ドラム 75 → 98%（ばらつきのある曲は 64〜69 → 88〜93%）・ベース 69 → 80%。ドラムの分かれ方 +6dB
  - 試してやめたもの：しきい値を大津の方法で（にじみまで拾う）・タム用の 4 つ目の音色（キックを取られる）
  - ギターとキーボードは AI なしでは見分けがほぼ付かないので「その他」のまま

- [x] AI で分ける（ANALYZER のレバー、2026-10-06）
  - MANEKKO の **ANALYZER** のレバー（上 = AI・下 = CLASSIC）：Demucs v4（htdemucs、MIT）で歌・ドラム・ベース・その他に分けてから、いつもの聞き取り（`refineHarmony`・`refineStems`・`melodyFromVocal`）に渡す（`src/cover/ai.ts`）
  - 部品：demucs-web（MIT・npm）。動かす土台 onnxruntime-web は使うときだけ CDN（jsDelivr）から、モデル（htdemucs_embedded.onnx・約 172MB）は初回だけ Hugging Face からダウンロードして Cache Storage（`bent-ai-models`）に保存。曲の音はどこにも送らない
  - WebGPU があれば使い、無ければ WASM。使えないとき（ダウンロード失敗・メモリ不足）は、お知らせを出していつもの方式に戻る
  - 速さ：WebGPU のあるパソコンで、28 秒の曲を約 29 秒（いつもの方式は約 2 秒）
  - 物差し（`npm run bench -- --ai`。モデルを `.cache/` に置く）：ドラムの分かれ方 +5 → +18.5dB。ただし物差しの歌は作り物の声なので AI は歌と認識しにくく（+1.5dB）、物差しでは歌の良し悪しを測れない。本物の曲で聞きくらべる
  - ギター・キーボードは htdemucs では「その他」のまま（ギター・ピアノも分ける htdemucs_6s もある。モデルが大きくなる）

## 精度（`scripts/cover-test.ts`）

- 合成した曲（ニ長調・120 BPM）：テンポ・調・小節の頭・コード 100%・キック／スネア 100%・メロディ 63%・ベース 94%
- 歌入りの曲（ハ長調・110 BPM、`vocal-test.ts`）：調とコード 100%（直す前は Em ばかり）・メロディ 91%（混ざった曲から）/ 89%（取り出した歌から）・分離 +15.9dB
- おもちゃで作った曲（ビート・ハウス・レゲエ）：テンポ ±3% 以内・コード 94〜100%・キック 93〜100%
- カバー（1〜7 台）：解析したメロディの 88〜98% を再現、和音を弾くおもちゃがいればコードは元と 80〜93% 同じ

本物の曲（歌・たくさんの楽器）では、テンポ・コード・ドラムはだいたい合うが、歌のメロディの聞き取りは難しい（似ている程度）。
